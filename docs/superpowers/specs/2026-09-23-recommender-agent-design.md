# 推荐检索与 Agent 工具调用项目设计

**日期：** 2026-09-23  
**目标：** 将现有图书推荐代码整理为可本地复现、可量化评测的推荐/检索主链路，并在其上提供可演示的 LLM 工具调用 Agent。

## 背景与边界

现有仓库包含 UserCF、ItemCF、Swing、双塔、LightGCN 等召回代码，三塔粗排、多目标 DCN 精排、CLIP+MMR 重排，以及 FastAPI/MySQL 服务入口。用户行为数据主要为模拟数据。当前训练实现和服务配置有已知问题，因此不能直接把 README 中的线上效果描述作为验收证据。

本轮以独立的本地演示链路为交付主体，复用并修复适合纳入主链路的现有代码。保留其他模型作为实验代码，但不要求所有历史模块都成为可靠生产组件。首轮运行不依赖 MySQL、外部图片下载或 GPU；LLM 访问通过环境变量配置的 OpenAI 兼容接口提供。模拟交互数据的指标只用于验证实现和比较基线，不代表真实业务收益。

## 设计

### 1. 本地推荐与检索服务

- 使用现有图书 CSV 作为演示目录，并提供确定性的加载、ID 映射和特征预处理。
- 提供关键词/内容检索、个性化推荐和图书详情三个稳定的 Python 接口；Agent 与命令行演示共用这些接口。
- 修复纳入主链路的粗排/精排模型模块注册、二元多目标损失、训练/推理模式和权重保存/恢复问题。加入固定随机种子及可复现的数据划分。
- 使用按用户时间顺序的留出划分，至少计算 Recall@K、NDCG@K 和 MRR@K；所有对照使用相同划分与候选范围，并包含简单基线。数据来自模拟交互，报告中必须说明限制。
- 首次运行不应逐条下载远程封面。文本检索及推荐主流程应能离线 CPU 启动；图像特征与 MMR 可以作为可选扩展。

### 2. 工具调用 Agent

- Agent 只调用注册的三个只读工具：`search_catalog`、`recommend_for_user`、`get_book_details`。工具参数用 schema 校验，工具响应使用结构化 JSON。
- 模型通过环境变量选择兼容服务的 base URL、模型名和 API key；凭证不写入仓库或日志。
- Agent 使用显式的工具调用循环，限制每轮可调用工具集合及最大轮数。回答中的书名和推荐理由必须能回溯到工具返回的图书字段；工具/模型错误返回清楚的错误，不执行任意 Python、SQL 或 shell。
- 测试不调用外部 LLM 服务；用可控的假客户端覆盖工具选择、参数校验、错误处理、轮数限制和结果引用。另提供人工可运行的真实模型演示步骤。

### 3. 文档与交付

- README 提供环境创建、离线运行、Agent 配置、评测命令、真实结果表和已知限制。
- 提供 `.env.example`，不包含真实密钥。
- 简历描述只使用实际运行产生的指标；若真实 LLM 凭证未配置，只表述 Agent 工具链实现和自动化验证，不宣称真实模型端到端效果。

## 验收标准

1. 在干净 Python 环境中可按文档运行离线演示，无 MySQL、GPU、网络图片或密钥依赖。
2. 自动化测试覆盖数据划分、排序指标、模型训练/权重恢复关键行为、三个工具及 Agent 工具调用循环。
3. 推荐评测结果可从命令重跑，记录数据划分、候选范围、随机种子、基线和实际数值；不预设提升幅度。
4. 使用真实兼容 LLM 服务配置时，Agent 能执行检索/推荐/详情工具并引用工具结果；无凭证时测试仍可完整通过。
5. README 清楚区分模拟数据上的离线结果、代码原型能力和未验证的生产/业务效果。

## 非目标

- 修复或部署 MySQL 服务链路。
- 将仓库里的每个历史实验模型全部纳入主链路。
- 声称工业规模、线上收益、真实业务指标或未实际测得的性能。
- 自动执行任何有副作用的工具操作。
