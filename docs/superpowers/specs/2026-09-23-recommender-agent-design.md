# 推荐检索与 Agent 工具调用项目设计

**日期：** 2026-09-23  
**目标：** 将现有图书推荐代码整理为可本地复现、可量化评测的推荐/检索主链路，并在其上提供可演示的 LLM 工具调用 Agent。

## 背景与边界

现有仓库包含 UserCF、ItemCF、Swing、双塔、LightGCN 等召回代码，三塔粗排、多目标 DCN 精排、CLIP+MMR 重排，以及 FastAPI/MySQL 服务入口。用户行为数据主要为模拟数据。当前训练实现和服务配置有已知问题，因此不能直接把 README 中的线上效果描述作为验收证据。

本轮先交付稳定的本地目录检索和推荐基线，再接入工具调用 Agent。旧的深度模型和 MySQL 服务作为实验/后续扩展，不阻塞 Agent 主流程。首轮运行不依赖 MySQL、外部图片下载或 GPU；LLM 调用使用 OpenAI Responses API 工具调用，密钥从环境变量读取。模拟交互数据的指标只用于验证实现和比较基线，不代表真实业务收益。

## 设计

### 1. 本地推荐与检索服务

- 使用现有图书 CSV 作为演示目录，并提供确定性的加载、ID 映射和特征预处理。
- 提供候选检索、候选用户偏好排序和图书详情核验三个稳定的 Python 接口；Agent 与命令行演示共用这些接口。
- 推荐基线至少包含热门度和 ItemCF，并处理已交互物品过滤、未知用户和无历史用户回退。先保证该路径可重复运行；双塔、LightGCN、粗排、精排等历史模型保留为实验，不作为首轮验收依赖。
- 排序接口接收用户 ID、检索 query 和候选 ID，返回重排结果及 query 匹配、用户历史/画像偏好等可解释分项；候选必须来自前一步检索，不能凭空添加。
- 使用固定随机种子和按用户时间顺序的留出划分，计算 Recall@K、NDCG@K 和 MRR@K。热门度与 ItemCF 使用相同的划分和候选范围。数据来自模拟交互，结果只描述该数据上的相对表现。
- 首次运行不应逐条下载远程封面。文本检索及推荐主流程应能离线 CPU 启动；图像特征与 MMR 可以作为可选扩展。

### 2. 工具调用 Agent

- Agent 只调用注册的三个只读工具：`search_catalog`、`rank_candidates_for_user`、`get_book_details`。工具参数用 schema 校验，工具响应使用结构化 JSON。
- 核心多步任务：结合指定用户的交互历史，找出符合主题、类别/关键词和价格限制的两本书，逐本查询详情核对条件，再依据真实字段说明理由。目录没有星级评分字段，任务和评测不得虚构评分条件或属性。
- 对需要个性化的任务，验收轨迹必须遵循“`search_catalog` 召回候选 → `rank_candidates_for_user` 按用户偏好排序 → `get_book_details` 核对入选书籍 → 基于字段证据作答”。不需要个性化的简单搜索可不调用排序工具。
- 评测集包含 20–30 条对话，覆盖单工具与多步工具调用、用户偏好、多个约束、结果为空、未知用户/图书及需要澄清的请求。简单请求可单步结束；需要历史和详情核验的任务应体现多步轨迹。
- 单独报告 Agent 指标：工具选择正确率、约束满足率、事实依据/书籍字段一致率、无结果与异常场景处理率，以及工具调用轨迹完整率。推荐排序指标与 Agent 指标分开呈现。
- 使用 OpenAI Responses API 的 JSON Schema 函数工具定义和显式调用循环。适配层从环境变量读取模型名、可选 base URL 与 API key；凭证不写入仓库或日志。
- 每轮记录可审查的 trace：会话/运行 ID、工具名、已校验参数、结果中的图书 ID、错误和耗时；不记录密钥。循环限制最大轮数，只能分发 allowlist 中的只读工具，不执行任意 Python、SQL 或 shell。
- 自动化测试不调用外部 LLM 服务；用可控的假客户端覆盖工具分发、参数校验、错误处理、轮数限制和来源字段关联。另提供真实模型评测命令，从环境变量加载凭证并保存每条评测轨迹与结果。真实模型评测只有在实际配置和运行后才可报告结果。

### 3. 文档与交付

- README 提供环境创建、离线运行、Agent 配置、评测命令、真实结果表和已知限制。
- 提供 `.env.example`，不包含真实密钥。
- 简历描述只使用实际运行产生的指标；若真实 LLM 凭证未配置，只表述 Agent 工具链实现和自动化验证，不宣称真实模型端到端效果。

## 验收标准

1. 在干净 Python 环境中可按文档运行离线演示，无 MySQL、GPU、网络图片或密钥依赖。
2. 自动化测试覆盖数据划分、排序指标、热门度/ItemCF、候选偏好排序、三个工具及 Agent 工具调用循环。
3. 推荐评测结果可从命令重跑，记录数据划分、候选范围、随机种子、基线和实际数值；不预设提升幅度。
4. 20–30 条 Agent 案例可用真实模型命令完整运行，保存实际工具轨迹及上述分项指标；分析失败案例，至少做一轮提示词/工具描述改进后重跑；没有真实模型运行记录时，不声称 Agent 评测效果。
5. 真实模型至少完成一条完整三工具个性化轨迹，并能依据详情字段回答；无凭证时本地测试仍可完整通过。
6. README 清楚区分模拟数据上的离线结果、代码原型能力和未验证的生产/业务效果。

## 非目标

- 修复或部署 MySQL 服务链路。
- 将仓库里的每个历史实验模型全部纳入主链路。
- 声称工业规模、线上收益、真实业务指标或未实际测得的性能。
- 自动执行任何有副作用的工具操作。
